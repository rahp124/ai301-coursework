# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Plan-context scope, approach and deviations against each substantive diff hunk and PR fidelity claims; evidence guide: Plan fidelity | The diff delivers the plan's bounded behavior and named deliverables, or the plan's deviation notes explicitly explain each addition, omission or changed approach. Description claims match the implementation. Ordinary supporting tests and necessary bookkeeping fit the boundary. Silent additions, silent omissions, or claims contradicted by the diff fail. | required |
| observable-testing | Plan test plan and repro artifacts against candidate test evidence, test hunks and description; evidence guide: Test evidence | Concrete commands or reproducible steps have actual observable results bearing on the changed behavior and the original trigger. Evidence supports the PR's claims, with limitations or failures stated honestly. A focused regression test or evidenced manual result may suffice when appropriate; test code alone, an unrun plan, 'works for me', or logs unrelated to the trigger fail. An honestly reported partial or cannot-reproduce result can pass when it establishes what was tried and observed and does not claim an unverified fix. | required |
| repo-checks | Repo-facts required checks (live CONTRIBUTING and CI) against test output and disclosed omissions; evidence guide: Test evidence | The repo's required checks have reported actual outcomes, or omitted/blocked checks are explicitly identified with reasons and bounded limitations. Disclosed unrelated failures are distinguished from failures introduced by this diff; an introduced failing check holds the PR. Silence about unrun required checks, or claiming a pass despite contrary output, fails. Explicitly pending CI before opening is a limitation, not a fabricated pass. | required |
| reviewable-diff | Candidate diff, changed-file stat and commit contents; evidence guide: Diff quality | Every substantive hunk belongs to the bounded issue change or a justified recorded deviation and a reviewer can trace the fix without unrelated churn, generated debris, debug output, or accidental files burying it. Judge relevance, not a file/line/commit-count threshold. A justified multi-file change passes; incidental whitespace alone need not fail unless it obscures review. | required |
| repo-requirements | Repo-facts template asks, contribution and AI policy and thread direction against title, description, commits and diff; evidence guide: Standards and comms | Every explicit applicable repository requirement is satisfied or an explicitly permitted exception is documented. Required template content, issue linkage, naming/commit conventions, seeded-marker removal, and disclosure must be present when the repo asks. Where AI disclosure is required, state use and extent (or an explicit no-use statement); silence fails. A general human-authorship rule is not by itself a disclosure demand. Explicitly no stated policy is a pass for that conditional requirement; missing policy evidence is unclear. Honest test limitations are handled by repo-checks, but disclosure cannot excuse forbidden content or bypass a hard policy. | required |
| reviewer-orientation | Title and description against issue, diff, evidence and stated review risks; evidence guide: Standards and comms | The draft gives a reviewer a concrete reason for the change and identifies the relevant behavior and remaining uncertainty. Terse specific text can pass; generic confidence without orientation fails. | preferred |

## Verdict rule

Accept exactly when every required check is pass. Any required fail or unclear means reject. Preferred grades are reported and never change the verdict. Report all checks, including conditional passes, with a deciding fact or quote. Do not turn an honest, evidenced shortfall into a failure merely because it falls short of ideal completeness; apply the individual conditions above. There is no third verdict.
